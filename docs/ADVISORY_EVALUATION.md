# Advisory evaluation and human review

`tools/evaluate_quality_50.py` freezes50 structured scenarios across baseline/candidates: normal validated/unvalidated findings, single/multiple defects, anomaly flags, invalid labels, missing metadata/SOP, contradictory evidence and malformed/unsupported requests.39cases request bounded advice;11test rejection of invalid evidence or unsupported intents. Rejections are not counted as valid model responses. Same case IDs/evidence are used across model candidates. Raw JSONL includes original response, validation reason, timings and resource samples where instrumented.

The preserved1B baseline returned26accepted/13fallback across39bounded cases;11other inputs were rejected. All original decisions were preserved. Seven normal/unvalidated cases triggered conservative rejection of invented anomaly claims. Other fallbacks included unobserved defect/capture claims and extra JSON content. These failures remain visible, rather than being hidden by relaxed validation.

The 3B challenger accepted39/39 bounded cases with the experimental guards. The selected1B adaptive-v1 prompt accepted37/39 experimentally and36/39 when the saved responses were replayed through the final, stricter claim guards. All invalid/unsupported cases were rejected and decisions preserved. See `Hardening_20261122/REPORT.md` and BENCHMARKS.json for exact comparisons. Compact-v1 returned prose and compact-v2 was stopped after15 poor trials; neither was selected. The production native worker now stops generation at a completed top-level JSON object. This boundary was installed after the paired benchmark and separately passed5 native tests and actual Pi integration; the earlier50-case acceptance counts are not relabeled as measurements of that final worker. This is not a full grammar-constrained decoder. No candidate can bypass schema/claim validation or change the detector's QA disposition.

Structured output includes inspection ID, summary, observed evidence, visual-only explanation, recommended actions, escalation flag, exact SOP references/approval state, limitations and generation status. Only the four bounded advisory strings are generated by Llama; immutable identity, evidence, decision and limitation fields are assembled by the application. The QA note is a draft, not an electronic release signature. Numeric confidence/bbox evidence remains in the immutable inspection and bounded prompt context; Llama may not alter it.

**Human evaluation is outstanding.** Automated guard acceptance is neither recommendation correctness nor pharmaceutical accuracy. Before operational use, authorized reviewers must score evidence consistency, explanation accuracy, recommendation appropriateness, SOP applicability, unsupported/unsafe claims and fallback handling, and supply approved SOPs. A review worksheet is included with the generated report. Do not label the evaluation human-validated until that worksheet is completed.

The current test set deliberately rejects unsupported free-form batch-summary input rather than inventing a batch inspection decision. Batch analytics and reports remain deterministic; individual advisories provide bounded operator assistance. Confidence/SKU/context validation has separate unit/integration cases; the original paired50-case set is not silently changed mid-comparison.
