# Database and audit

SQLite WAL and FULL synchronous writes, connection-local foreign keys, bounded connection timeout and `BEGIN IMMEDIATE` serialize audit mutations. Schema v2 adds batches, station settings, advisory jobs, audit events, replay IDs, batch/image indexes and batch linkage checks. Legacy rows remain in LEGACY; decisions/evidence are not rewritten. Original-source/decision/severity/JSON/batch/image-identity updates and deletes are blocked by SQL triggers. Human reviews append to QA events; latest-review and advice are projections and do not replace the original decision.

Each audit event includes ID, actor, type, timestamp, previous SHA-256, canonical JSON payload and current SHA-256. New inspection events seal canonical record hashes. Advisory regeneration appends full advisory-history events, preserving earlier outputs even when the current advice projection changes. Full integrity verification also checks saved original-image and exact source-file hashes where present. Uploaded/local source bytes are retained separately from the rendered JPEG original view; camera records identify their decoded-frame/JPEG representation. Imported legacy images have no retroactive authenticity guarantee. **An unkeyed hash chain cannot prevent a privileged attacker replacing the entire database.** Keep external backup/head hashes and preserve physical access controls; no regulatory certification is claimed.

Failed operational SQLite writes create durable JSON operations in `spool/`, using fsync and atomic rename. Recovery replays in order and transactionally records operation IDs so replay is idempotent. A maintenance thread retries every5seconds; unrecoverable operations remain for investigation. Full-disk failures propagate as faults rather than accepted products. Storage warnings occur below1GiB, controlled inspection blocking below0.25GiB. No automatic evidence deletion/retention purge exists. Retention means manual, authorized, verified archival.

`Store.backup()` uses SQLite backup API for a consistent snapshot; copied DB alone does not contain image files. Backup JSON reports its SHA-256. `tools/database_maintenance.py restore SNAPSHOT NEW_DIRECTORY --images IMAGE_DIRECTORY` restores into a new directory only, checks SQLite and audit integrity, and never overwrites original data. Backup/restoration, failed write/spool replay, concurrent transactions, immutable rows and tamper detection were executed in automated tests; target integration evidence is separate.

Authenticated mutation actions are audited without passwords/tokens. Local PBKDF2 credentials, bounded expiring sessions, role checks and SameSite/HttpOnly session cookies provide offline accounts. First account setup is local-only and one-time. Administrator manages maintenance; supervisor creates/closes batches and appends QA reviews; operator inspects/requests advice; auditor reads. The older display PIN does not authenticate users.
